# FBLIVE2 — Facebook 直播本地分析工具

Windows 本地工具，输入 Facebook 直播录像链接，或导入本地音视频／逐字稿，生成带时间戳的完整逐字稿与可追溯的内容复盘。

## Vercel 网页工作台（1.1）

网页位于 https://fb-live-analyzer.vercel.app 。网页托管在 Vercel，下载、转录、分析及文件保存仍在本机。完整解压 Online 版本后，运行 `Start-Online.cmd` 自动启动并配对；旧版 EXE 不支持网页连接。详见 [线上工作台使用说明](线上工作台使用说明.md)。

Vercel 部署目录为 `web/`，不上传模型、录像、EXE、会话令牌或分析历史。源码方式可运行 `python tool.py --portal https://fb-live-analyzer.vercel.app`；在线打包使用 `build.ps1 -Online`。本地处理程序仅监听 127.0.0.1，只有指定网站来源及正确会话令牌才能调用 API。

## 本地使用

打包完成后，双击 `FBLIVE2.exe`，会自动打开本机浏览器界面。无需安装 Python，无需 API Key。源码运行方式见下文。

1. 输入 Facebook 录像链接，或导入 MP4、MP3 等本地音视频。
2. 可选导入已有 SRT、VTT、TXT、JSON 逐字稿，以及留言 CSV。
3. 点击「开始转录与分析」。本机 CPU 完成语音转录；首次使用会下载所选语音模型，以后复用。
4. 查看完整逐字稿、语言风格线索、优点、待改进之处及对应证据。
5. 导出逐字稿 TXT、SRT、JSON，以及分析报告 HTML、Markdown。HTML 报告可打印为 PDF。

所有任务、音视频、模型缓存和报告存放在程序旁的 `FB_Live_Data` 文件夹。关闭浏览器不会停止任务；点击界面的「关闭工具」结束进程。

如果浏览器没有自动打开，可查看 `FB_Live_Data/local-address.txt` 中的本机地址。程序首次解压运行库时可能需要数秒。

## 直播类型与目标（跨行业）

工具不假设直播在卖东西。贴入链接或导入文件后，会按内容关键词给出一个**类型建议**，可在「转录与分析设置」里先指定，也可在报告页的「修改类型与目标」里随时改，改完只重算分析，不重新下载或转录。

| 类型 | 默认目标 | 接外部数据后才能验证 |
| --- | --- | --- |
| 商品销售 | 了解需求／咨询、购买意向 | 付款订单、实收金额 |
| 课程／教学 | 理解／练习参与、报名意向 | 报名、完成率、测验结果 |
| 房产／服务 | 了解需求／咨询、预约意向 | 预约、有效线索、成交 |
| 品牌／新品 | 观点交流／提问、体验意向 | 链接点击、试用申请 |
| 访谈／社群 | 观点交流／提问、活动参与 | 活动报名、社群加入 |
| 娱乐／游戏 | 活动参与、关注／订阅意向 | 关注、订阅、打赏 |

目标可多选，一场直播可以同时有教学和销售段落。自动识别只是规则建议，报告里会标注「规则建议，待确认」或「用户指定」。

## 通用 Dashboard（六个模块）

所有行业共用同一套呈现：**直播总览**（时长、观看、Reactions、分享、留言人数）、**内容地图**（五分钟窗口的主题与时长）、**互动时间轴**（每分钟留言与目标信号）、**观众洞察**（高频需求、疑虑、正负面反馈）、**目标行动**（与本场目标相关的询问和意向）、**复盘建议**（有证据的建议与候选剪辑片段）。每一行都能跳回原文证据。

「目标行动」只统计留言里可核对的**信号**，实际成交、报名、预约一律显示「未取得」，要接入订单、课程系统或 CRM 数据才能验证。没取得的数据不补造。

## 分析方式

- **本地规则初筛**：无需语言模型。按逐字稿识别教学讲解、互动邀请、促销、故事及演示语言线索，展示原文和时间戳。关键词线索不等于质量评分，建议需要复核。
- **本地 AI 复盘（可选）**：如果本机已运行 Ollama，并已有语言模型，在设置里选择模型。工具会逐块覆盖全部逐字稿，并验证每条结论引用的证据编号。文字和留言仅发送到 `127.0.0.1:11434`，不调用云端 AI。
- **交给聊天进一步分析**：点击「复制给 AI 进一步复盘」，或导出完整资料 JSON 后发到聊天，可以继续由助手分析。

本版本基于逐字稿评价内容及语言表达方式，不直接分析声调、表情、肢体和镜头。

## 完整逐字稿

本地语音识别使用 faster-whisper，默认 `small` 多语言模型，CPU int8。可改用 `base`、`tiny`、`medium`、`large-v3`。模型越大，下载量、内存和处理时间通常越高。自动识别的人名、价格、数字及混合语言请回听核对。

导入 SRT/VTT 时保留真实起止时间；纯文本没有时间戳也可分析，但不会编造时间。只有全部片段有真实起止时间时才提供 SRT 导出。

## 取得留言

链接拿不到留言，下载器也不行。我试过 `facebook-scraper`：它依赖的 `m.facebook.com` 和 `mbasic.facebook.com` 现在直接返回 HTTP 400，对公开主页也返回 0 条，所以没有采用。

有两条可用的路，按你愿不愿意付费选。

### A. Apify（从链接直接抓，按量计费）

勾选「高级设置」里的**通过 Apify 抓留言与互动数**。工具会调用 `apify/facebook-comments-scraper` 取留言和回复，再用 `apify/facebook-posts-scraper` 补 Like、留言数和分享数这些页面计数。

令牌放在工具目录的 `.env` 里，一行即可，`.gitignore` 已经排除这个文件：

```
APIFY_TOKEN=你的令牌
```

改完重启工具，选项才会可用。令牌只在请求头里发给 Apify，不写进报告、导出和日志。Apify 按用量计费（留言约 US$1.40 / 1000 条），所以这个开关默认关闭，每次运行都要自己勾，并且有条数上限。

两点如实说明：Apify 返回的回复只带层级、不带父留言 ID，所以回复归属是按线程顺序推断的，报告里会标出推断了多少条；没填直播开始时间时，工具用贴文发布时间当对齐起点，这也是推断，不是确认的开播时刻。

### B. 浏览器脚本（免费，自己跑）

另一条路是浏览器脚本 [`scripts/collect-comments.js`](scripts/collect-comments.js)：

1. 在工具里点「留言 CSV」旁边的**复制留言采集脚本**
2. 到你能正常看到留言的 Facebook 视频／贴文页面，按 F12 打开 Console，粘贴回车
3. 脚本会反复点开「查看更多留言」和回复，然后下载一份 CSV
4. 回到工具选这个 CSV，并在「高级设置」里填直播开始时间（含时区）

脚本只读页面上已经渲染的内容，不调接口、不外发数据、不点赞或回复。导出的时间是留言发布时间，换算成直播内的分秒要靠直播开始时间；认不出的时间格式保持为空，工具会标成未对齐而不是猜一个。Facebook 的页面结构随时会变，采不到时需要改脚本里的选择器。

如果这场直播在你自己管理的专页上，用 Graph API 取 `/{video-id}/comments` 和 `/reactions` 比脚本稳定得多。

## 留言格式

CSV 内容列支持 `text`、`comment`、`message`、`留言`、`内容`；时间列支持 `timestamp`、`created_time`、`time`、`时间`、`相对时间`、`发布时间`。可选列：`id` / `comment_id`、`user_id` / `username`、`parent_id`。

留言按实际 ID 去重，保留回复关系，用户 ID 在输出里匿名化。时间支持相对秒数、HH:MM:SS、ISO 日期时间或 Unix 秒；绝对时间需要在设置中填写带时区的直播开始时间，例如 `2026-10-18T15:00:00+08:00`。录像剪掉开头时，填写裁剪秒数。

## Facebook 数据边界

默认只尝试下载公开可访问、已结束的直播录像，不绕过访问控制。部分链接会因登录、权限、年龄限制、地区或平台变化无法下载，可导入你已有的录像继续。

需要登录才能看的录像，可以在「01 放入这场直播」里选一个 Netscape 格式的 `cookies.txt`（浏览器扩展导出）。工具把它交给下载器，以**你本人的登录身份**访问这条链接，等于你自己在浏览器里打开它；它只用于下载，不会写进报告或任何导出文件，任务一结束就从 `uploads` 删除。cookies 等同于你的 Facebook 登录凭证，不要分享给别人，也不要放进 git。别人的私密内容不会因为导入 cookies 就变成你有权使用的素材。

下载录像不代表取得了留言、Reactions 或分享，**导入 cookies 也不会**：工具从不抓取留言内容，留言一律靠 CSV 补充；互动指标只展示下载器实际返回的字段。缺失值保留为缺失，不以 0 替代，不从整场总数推算每分钟曲线。互动数量不等于成交。

已用独立 EXE 完成合成语音转录、导出，以及真实 Facebook 录像 90 秒中文片段的转录验收。该实际录像全长约 2 小时 37 分，尚未完成整场转录验收，也未人工回听确认所有识别文字。详细结果见 [使用验收清单](使用验收清单.md)。

## 源码运行

需要 Python 3.12（Windows 64 位）：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe tool.py
```

## Windows 打包

运行 `build.ps1`，产物位于 `dist/FBLIVE2.exe`。首次构建会下载 Python 依赖；`requirements-lock.txt` 固定本次实际验证的版本，其中 PyAV 固定为 16.1.0，以匹配 faster-whisper 的音频解码接口。语音模型不打进 EXE，在首次使用时下载到本地缓存。发布时请同时附上生成的 `THIRD_PARTY_NOTICES.txt`。

## 开源组件

- [yt-dlp](https://github.com/yt-dlp/yt-dlp)：录像获取；项目源码为 Unlicense，打包组件许可需分别核对。
- [faster-whisper](https://github.com/SYSTRAN/faster-whisper)：MIT，本机多语言语音转录；使用 CTranslate2 和 PyAV，音频解码无需额外安装 FFmpeg 程序。
- [Ollama](https://github.com/ollama/ollama)：可选本地语义分析服务，本工具不自动安装它或下载其语言模型。
- PyInstaller：仅用于 Windows 打包；保留其运行时许可例外。

此仓库用于 private 源码备份，不包含用户直播资料、模型缓存、密钥或大型打包产物。
